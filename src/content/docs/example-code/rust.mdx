Rust's standard library does not include an HTTP client. This example uses [`reqwest`](https://docs.rs/reqwest/) for HTTP and [`serde_json`](https://docs.rs/serde_json/) to build the JSON request body.

Add the dependencies to your `Cargo.toml`:

```toml
[dependencies]
reqwest = { version = "0.12", features = ["blocking", "json"] }
serde_json = "1"
```

```rust
use serde_json::json;
use std::error::Error;

fn main() -> Result<(), Box<dyn Error>> {
    let user_id = "your-user-id";
    let api_key = "your-api-key";

    let client = reqwest::blocking::Client::new();
    let payload = json!({
        "html": "<div class='box'>Rust ✅</div>",
        "css": ".box { border: 4px solid #03B875; padding: 20px; font-family: Roboto, sans-serif; }",
        "google_fonts": "Roboto"
    });

    let response = client
        .post("https://hcti.io/v1/image")
        .basic_auth(user_id, Some(api_key))
        .json(&payload)
        .send()?
        .error_for_status()?;

    let body = response.text()?;
    println!("{body}");

    // {"url":"https://hcti.io/v1/image/1113184e-419f-49f1-b231-2069942a186f"}
    Ok(())
}
```

## Rendering from an async Rust service

A Rust service might calculate account statistics, process events, or build a customer activity feed. When you need a shareable summary of that data, send an HTML card to HCTI and store the returned image URL with the result. Your service handles the data processing without also managing Chromium processes.

The example above uses blocking `reqwest` for a command-line program. In a Tokio application, use the [async `reqwest::Client`](https://docs.rs/reqwest/latest/reqwest/struct.Client.html) and await the request. Reuse the client for its connection pool and limit how many renders you submit concurrently. A fast Rust backend still has to wait for the network and browser rendering, so generate frequently requested images ahead of time when possible.
