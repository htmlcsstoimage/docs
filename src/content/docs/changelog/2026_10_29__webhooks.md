You can now **receive webhook events from your HCTI organization**. Publish content after an image reaches storage, keep your application in sync with template changes, or trigger alerts when usage crosses a threshold.

Open [Webhooks in the dashboard](https://htmlcsstoimage.com/dashboard/webhooks) to add an endpoint and choose its events. You can also manage webhooks through the [Management API](/management-api/webhooks/) or [MCP tools](/integrations/mcp/tools/#webhooks).

- Subscribe to image storage and deletion, resource creation and changes, plan changes, usage resets, and usage alerts.
- Verify signed deliveries, and configure custom headers or query parameters for your receiver.
- Inspect event payloads, delivery attempts, and HTTP results in the dashboard.
- Build around a consistent event envelope with stable event IDs. Stored credentials are excluded from payloads, and large text fields can be truncated.

Delivery is **at least once**, with automatic retries for temporary failures. Receivers should handle duplicates and events arriving out of order. Creating an image URL does not trigger rendering, so request the image before expecting an `image_stored` event.

See the [webhooks guide](/guides/webhooks/) for setup, event definitions and example payloads, delivery guarantees, and a runnable receiver with signature verification and durable deduplication.
